## 2025-01-28 - Optimizing Array Processing in Report Generators
**Learning:** Found significant array processing overhead in `generateWorkflowReport`: O(N*M) nested `.find()` iterations, static redundant `.flatMap()` aggregations within `.map()` closures, and multiple `.filter().length` passes for counting on the same dataset. This architectural pattern caused huge performance penalties, especially when processing numerous workflows and tasks.
**Action:** Always verify if constant data derivations (`.flatMap()` or other processing) inside a `.map()` can be hoisted out. Convert O(N*M) nested `.find()` into an O(1) `Map` lookup over the constant list before mapping. Consolidate multiple aggregate counters into a single `for` loop over the dataset rather than chaining multiple array iterations.
