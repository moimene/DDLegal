## 2024-04-18 - Replacing N*M lookup loops with O(1) Maps in Aggregate APIs
**Learning:** In the Dashboard aggregate API route (`src/app/api/dashboard/aggregate/route.ts`), there were heavy O(N*M) lookups inside `.map()` arrays because of inline `.filter()` and `.find()` array methods referencing other large arrays (`allTasks`, `allScores`, `projectsRes`). As data scales (more projects, tasks, workflows), this architecture-specific looping design can severely degrade aggregation performance. Grouping related items by key or normalizing the source arrays to use O(1) Map lookups dramatically improves server response time for complex dashboards.
**Action:** When grouping multiple items by a shared key to eliminate O(N²) `.filter()` lookups inside loops, pre-compute a Map that associates the key with an array of items or properties outside of the iteration block. Always check for inner `.filter()`/`.find()` operations when reviewing large `.map()` aggregations.
