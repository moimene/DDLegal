## 2024-06-19 - O(1) Map lookups for dashboard aggregations
**Learning:** Found an N*M complexity bottleneck in `src/app/api/dashboard/aggregate/route.ts` where arrays were repeatedly scanned inside a `projects.map()` call using `.filter` and `.find`. I also learned that when converting an array ordered by `created_at DESC` into a Map, we must manually iterate and conditionally set keys if they don't already exist (`if (!map.has(key)) map.set(key, item)`) to preserve the latest record, as standard `new Map(array.map(...))` overwrites older elements with newer ones.
**Action:** When aggregating related records across multiple projects (like tasks, workflows, and scores), always pre-process the raw data into `Map` structures in a single pass O(N) before iterating over the projects array O(P). This reduces the complexity from O(P * N) to O(P + N).
