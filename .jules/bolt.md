## 2024-05-18 - Architecture-specific Array Loop Hoisting and Map Lookups
**Learning:** Found significant O(N^2) overhead in workflow and reporting engines (e.g., `instance-runner.ts` and `report-generator.ts`). The `.map()` loops inside these areas were repeatedly performing nested `.find()` iterations over large arrays of findings, and worse, performing static text replacements inside the loop or repeatedly computing `.flatMap()` logic. This violates architecture-specific array processing patterns.
**Action:** Always pre-compute O(1) Maps sequentially before array iterations and hoist static calculations outside the loop. Use single passes to count and construct map dependencies (like `hitlByFindingTitle`) rather than applying separate `.filter().length` traversal for severities and status lookups.
