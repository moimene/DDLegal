## 2024-10-14 - Pre-computing Map keys before looping and hoisting loops
**Learning:** Found multiple instances where an `O(N)` loop operation (`.find()`) inside another `O(N)` mapping array function caused severe `O(N^2)` bottlenecks, specifically when matching properties with calculated fields (like slug formatting) inside the search condition. Also, finding operations that repeatedly run the exact same `flatMap` mapping iterations for evidence inside a map mapping without depending on the loop arguments results in unnecessary allocation overhead.
**Action:** Always pre-compute Map structures before iterating over mapped arrays to avoid nested `O(N)` lookup complexities (turning `O(N^2)` performance to `O(N)` performance), and always hoist redundant data formatting transformations out of the loops when possible.
