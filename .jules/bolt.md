## 2025-02-23 - O(N*M) bottlenecks in nested .find() and .filter() calls within .map() arrays
**Learning:** Found a specific pattern in dashboard aggregation (`src/app/api/dashboard/aggregate/route.ts`) where `.filter()` and `.find()` were used extensively inside `.map()` array iterations, leading to unnecessary repetitive overhead from N*M allocations and comparisons. This type of bottleneck happens when multiple relationships between main entities (e.g. projects) and child entities (e.g. tasks, workflows) are resolved synchronously in memory.
**Action:** Always pre-compute O(1) HashMaps (or Maps of Arrays for `filter` equivalents) prior to the `map` loop for all inner lookups. For `find`, use `if (!map.has(key)) map.set(key, item)` to match the first occurrence behavior of `.find()`.
