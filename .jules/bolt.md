## 2024-10-12 - Replacing O(N²) nested lookups with O(1) Map pre-computation in API routes
**Learning:** Found O(N²) performance bottlenecks in `src/app/api/dashboard/aggregate/route.ts` caused by using `.find()` and `.filter()` over all tasks, scores, and workflows repeatedly inside `.map()` loops when building the response payloads (e.g., `projects.map(...)`, `myTasks.map(...)`, `alerts.map(...)`). These nested loops run on large datasets and can cause blocking behavior.
**Action:** When aggregating large datasets across different entities (projects, tasks, scores, workflows), pre-compute Maps indexed by a common key (like `project_id`) prior to iterating. This converts O(N*M) nested lookups to single O(N) mapping passes followed by O(1) loop lookups, significantly reducing data processing latency.
